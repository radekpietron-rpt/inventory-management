01 — System Architecture

Three tiers, one process each, no database

A single-page Vue application talks directly to a single-file FastAPI service over HTTP. There is no Vite proxy — the SPA calls the API origin directly, which is why CORS is fully open. All data is loaded from JSON files into Python lists at startup; nothing persists across restarts.

03 — Data Flow

Request lifecycle: filter change to rendered chart

The four global filters (Time Period, Warehouse, Category, Order Status) live in one shared composable and drive every view the same way.

User changes a filter in FilterBar.vue
FilterBar writes to module-scope refs in useFilters.js — a singleton shared by every component that imports it.
Views react via watchers
Each routed view watches the filter refs and re-triggers its load function with getCurrentFilters() (maps UI "location" to API "warehouse", "period" to "month").
api.js builds the request
Appends only non-all filters as query params, then issues axios.get("http://localhost:8001/api/…").
FastAPI filters in-memory lists
apply_filters() matches warehouse exactly and category/status case-insensitively; filter_by_month() handles both months (2025-01) and quarters (Q1-2025) via substring match on order_date.
Pydantic validates and serializes
Routes with a response_model coerce the raw dicts into typed models; summary/report endpoints compute aggregates on the fly and return plain JSON.
Raw data lands in refs, derivations in computeds
Views store responses in refs (allOrders, inventoryItems, …); computed properties derive table rows, KPI tiles, and chart coordinates, which render as custom SVG.

06 — Observations

Worth knowing before you build on it

Client calls endpoints the server does not implement
api.js defines task CRUD (GET/POST /api/tasks, PATCH/DELETE /api/tasks/{id}) and purchase-order calls (POST /api/purchase-orders, GET /api/purchase-orders/{backlog_item_id}) — none exist in main.py. The PurchaseOrder and CreatePurchaseOrderRequest Pydantic models are declared but unused by any route; purchase_orders.json only feeds the has_purchase_order flag on /api/backlog. App.vue's task loading fails silently (caught, console-logged). Likely work-in-progress on this new_features branch.
Backlog.vue is unreachable
The view exists with full stats and table logic but has no route in main.js; backlog data is instead shown inside Dashboard with BacklogDetailModal.
Demo-grade by design
No auth, wildcard CORS, no rate limiting, no persistence — all intentional for a workshop. Business rules to remember: revenue goal is $800K/month (or $9.6M YTD across all months); inventory has no time dimension so the month filter never applies to it.
Public repository
The repo and any fork are public. client/.npmrc pins the public npm registry and the client lockfile is gitignored — both guard against leaking internal registry URLs and must stay in place.
